# Контракт: оценка дизайнера из CRM → HUB

Этот документ — готовое ТЗ для треда с CRM (заказ-наряды).

## Цель

Когда менеджер CRM оценивает выполненную 3D-работу исполнителя (дизайнера HUB),
CRM отправляет оценку в HUB. HUB обновляет рейтинг дизайнера; админ-панель HUB
показывает лидерборд.

## Когда слать

После того как заказ-наряд / modeling brief в CRM отмечен выполненным по 3D
**и** менеджер выставил оценку (1–5). Не слать при черновиках и невыполненных работах.

Рекомендуемый триггер в CRM: сохранение оценки менеджером на карточке
выполненного 3D-заказа, у которого уже есть `hub_brief_id` / `brief_id` из HUB.

## Endpoint

```
POST {HUB_BASE_URL}/api/v1/briefs/{brief_id}/ratings
```

- `{brief_id}` — публичный id брифа в HUB (тот же, что вернул `POST /api/v1/briefs`).
- Auth: **тот же SITE HMAC**, что для создания брифов / STL.

### Заголовки

| Header | Значение |
|--------|----------|
| `Authorization` | `Bearer <site_token>` |
| `X-Site-Id` | `<site_id>` |
| `X-Timestamp` | unix seconds (строка) |
| `X-Signature` | `hex(hmac_sha256(site_secret, timestamp + "\n" + raw_body))` |
| `Content-Type` | `application/json` |

Подпись считается от **сырого JSON body** (как у `POST /api/v1/briefs`).

### Body (JSON)

```json
{
  "event_id": "crm-rating-site1-12-1710000000",
  "score": 5,
  "comment": "Отличная модель, всё по ТЗ",
  "rated_by": "Иванов И.И.",
  "local_brief_id": 12
}
```

| Поле | Тип | Обязательно | Описание |
|------|-----|-------------|----------|
| `event_id` | string ≤64 | да | Уникальный id события. **Идемпотентность**: повтор с тем же `event_id` не создаёт вторую оценку. |
| `score` | int 1..5 | да | Оценка менеджера |
| `comment` | string | нет | Комментарий к оценке |
| `rated_by` | string ≤255 | нет | ФИО/логин менеджера CRM |
| `local_brief_id` | int | нет | Локальный id в CRM; если передан — должен совпасть с brief в HUB |

### Успешный ответ `200`

```json
{
  "status": "created",
  "event_id": "crm-rating-site1-12-1710000000",
  "brief_id": "…uuid…",
  "designer_id": 3,
  "designer_name": "Петров П.П.",
  "score": 5,
  "avg_rating": "4.50",
  "ratings_count": 2
}
```

При повторе того же `event_id`: `"status": "duplicate"` (оценка не дублируется).

### Ошибки

| HTTP | Когда |
|------|--------|
| `401` | HMAC / token / site_id неверны |
| `400` | нет дизайнера на брифе, `score` вне 1..5, `local_brief_id` не совпал |
| `404` | brief не найден для этой точки |

## Правила на стороне CRM

1. Оценивать только brief со статусом «готово» в HUB (или локально done + был push в HUB).
2. `event_id` строить стабильно, например: `rating-{site_id}-{local_brief_id}-{rating_version}`.
3. Не пересчитывать среднее на стороне CRM — источник истины средний балл в HUB (`avg_rating`).
4. Если brief ещё не назначен дизайнеру — HUB вернёт `400`; CRM показывает ошибку менеджеру.

## Что НЕ входит в этот контракт

- Удаление/изменение оценки (пока нет API).
- Оценка без привязки к brief.
- UI рейтинга в CRM (опционально позже можно читать `avg_rating` из ответа).

## Smoke-check после внедрения в CRM

1. Взять done-brief с назначенным дизайнером.
2. `POST .../ratings` с новым `event_id`, `score=5`.
3. Повторить тот же запрос → `status=duplicate`.
4. В HUB открыть `/portal-admin/` → дизайнер в таблице рейтинга с обновлённым баллом.
